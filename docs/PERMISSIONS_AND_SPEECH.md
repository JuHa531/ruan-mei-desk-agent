# 权限、工具次数与朗读（2026-11-08）

设置里的「执行权限」有三档，默认帮我批准，保存后下一条需求生效：

- 请求批准：每项需求先确认；每次工具执行前再展示具体参数，批准仅对这一次有效。
- 帮我批准：正常查询和新建工作目录内文件直接执行；任意非白名单命令、安装、覆盖文件、删除记忆、危险按键、手机操作及工作目录外路径需要批准。
- 完全批准：应用不再请求批准，执行器放行路径和命令限制，使用当前 Windows 账号权限；不绕过操作系统权限或服务商限制。

批准状态由服务端持有，拒绝或停止后不再执行后续工具。主界面显示批准卡，桌宠聊天弹出同一请求的批准窗口。设置保存在不纳入 Git 的 app/permissions.local.json。原有本机来源校验和请求格式校验保留。

工具循环默认不设轮数上限。需求里写「最多 3 轮」或「最多调用 5 次工具」可限定本轮任务；轮数指一批模型工具请求，次数指单个工具。工具卡默认折叠，点标题才能查看参数和输出。主界面「停止任务」可取消待批准或后续调用；已开始的外部程序不能自动撤回。

朗读与重播从准备到播放完毕互斥，其他重播按钮在此期间禁用。网页 Audio 必须收到 ended 才解除占用，桌宠聊天也拒绝另一条朗读抢占。主界面流式缓存只有片段齐全、没有失败、文本全部覆盖才保存；缺片段时重播重新合成完整正文。完整缓存不会再次裁剪。此互斥分别覆盖主界面和桌宠聊天各自的播放器，尚不是全系统音频独占。

括号内容保留，语音输入中转为逗号停顿，连续逗号不升级为句号；前端切块尽量保持括号和引号成对。保留原有句末标点及低音量尾音。音色权重、参考、原生速度和既定停顿参数未改，未重新训练。实际样本的识别完整性不能代替自然度试听。

验证脚本：scripts/test_agent_controls.py、scripts/test_speech_exclusive.mjs、scripts/test_speech_queue.mjs、scripts/test_bilingual_role.py；浏览器实测完整播放及互斥，桌宠聊天测试覆盖拒绝第二条朗读与停止后的恢复。
