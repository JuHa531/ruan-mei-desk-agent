# 语音服务内存（2026-11-06）

语音合成（9880）、适配器（9881）和语音识别（9882）是不同服务。Windows venv 的几 MB 启动器不是另一份模型。

- 合成模型继续常驻 GPU，保留原有半精度、音色、速度、停顿和推理加速。
- 包装入口在启动期间对 ZIP 检查点使用 mmap，加载结束恢复原始 torch.load，收集临时对象和未使用的 CUDA 分配。不修改上游模型源码。
- healthz 返回已加载权重路径；启动脚本路径匹配时跳过重复加载，路径不匹配仍执行原有加载和重试。
- 识别默认按需加载。未用麦克风时，实测从约 838 MiB 降至约 21 MiB；首次识别需要额外加载时间，用过以后继续保留模型。设置环境变量 `RM_ASR_PRELOAD=1` 并重启识别服务可恢复启动预加载。
- ASR healthz 的 ok 表示接口可用，loaded 表示模型是否已加载；检查健康状态不会触发加载。

限制：减少启动峰值不等于同等幅度降低预热后的常驻内存。合成主进程仍需数 GB，本轮不能承诺大幅减少它的常驻占用。未采用量化、CPU 卸载或定时驱逐工作集。

试验过归还 CRT 空闲堆块，但试验期间后端异常退出，因未满足稳定性要求已全部撤回。没有在正式入口保留该机制。

验证：scripts/test_voice_startup_memory.py 检查 mmap 作用范围及失败恢复；原音乐语音恢复和英文路由测试通过。实际合成测量及音频保存在 work/voice-memory-20261106。短句基准不能代表所有文本和负载；不同进程的 PCM 存在浮点差异，不能声称逐字节不变或以此代替听感验收。
